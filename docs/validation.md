## 教材架構基礎驗收

- 新科目及知識點可透過 JSON 後台建立，題目可多知識點映射，不需要重寫模型。
- 缺少參照、任意資料表名稱、未知欄位、無效日期及前置知識循環會拒絕並回滾。
- 待核驗版本不能透過匯入自稱已核驗；原創 seed 不能直接正式發布。
- PostgreSQL migration 在 PGlite 真實 PostgreSQL 引擎執行成功；所有 public 表有 RLS。
- PostgreSQL 角色測試：家長僅看同家庭、學生僅看自己、不能自行改角色、不能讀取含答案的題目版本。
- PostgreSQL trigger 另外拒絕作者自行審核，以及缺來源查核的發布。
- PGlite 並非 Supabase 遠端連線、Auth 或 Storage 驗證。

## 正式建置啟動與可重現性

`npm ci` 依鎖定檔重裝成功，之後資料庫初始化、型別檢查與正式建置再次通過。`npm start` 啟動後，以實際 HTTP 請求確認首頁 200、未登入 API 401、本地 session 可讀取學生摘要、無家長授權時開始任務 403。主資料庫仍為零星星、無家長授權、只有五題原創 seed；端到端測試的假審核與發布只保存在專用 E2E 資料庫。

雲端草稿已保存 `install_script` 與 `start_skill`。這只代表設定持久化，尚未發布 snapshot，也未驗證新任務還原。使用者需在環境設定檢視及儲存變更，再發布環境。
