# 架構與階段驗收

## 資料流

React 表單／答題 → 同源 API → Zod → session 角色與家庭授權 → 業務服務 → SQLite 交易。Phaser 僅讀取衍生進度及發出探索動作；不持有答案、點數權威值或資料庫連線。答題前不回傳正確答案，作答後回傳解說。

首版採單機 Node.js 24，SQLite WAL 與 BEGIN IMMEDIATE，適合本地驗證，不主張橫向擴展。未來切換 PostgreSQL 時，保留領域規則，將 repository 改為 PostgreSQL 交易與列鎖；不能直接把此 SQLite 檔案放進多個無狀態執行個體。

## 課綱與版本模型

課綱 → 學習內容／表現 → 知識點，另以素養 mapping 建立能力指標。學年度、科目、出版社及版本組成版本身份；冊次含年級、學期；單元及小節保留來源。小節—知識點、題目—知識點均多對多；學生掌握紀錄使用 student + objective 主鍵。

`grade_subject_availability` 由有來源的設定建立，不以主觀假設預填適用年級。各科選書以 student + subject + academic_year 主鍵保存，切換出版社不清除知識點紀錄。後台可建置新科目、學年度、出版社、冊次、小節及知識點；版本僅能匯入待核驗狀態。

PostgreSQL migration 同時提供完整基礎模型、外鍵、版本唯一約束與 RLS。PGlite 測試驗證 PostgreSQL SQL 與權限；不是遠端 Supabase Auth、Storage 或部署驗收。

## 階段一：可執行學習循環

已實作學生五題原創任務、提示、伺服器判分、錯題與知識點觀察、重啟持久化、家長本地授權、家庭約定、冪等兌換、每日任務上限、星星帳本、寵物衍生成長、教材草稿及獨立審核、基本發布閘門。

主要驗收：無授權不能開始、跨家庭拒絕、答案不預洩、重送不改首次答案／不重扣、任務有終點、資料重新開啟仍在、未核驗資料不能直接發布。精確結果見 validation.md。

## 階段二：教材建置與雲端帳戶

本次已交付可用的本地教材架構匯入、參照查核、多對多映射、前置知識循環防護及 PostgreSQL 結構。尚待：來源檔案／目錄證據保存、完整冊次審查、批次撤回、內容編輯及新版本、完整出版社版本逐章核驗、學校進度選擇、正式課程取題。

正式帳戶須使用 Supabase Auth（家長可驗證帳戶、受監護學生登入）、server-side session 及 RLS；建立 Storage 私有 bucket、檔案授權、資料刪除／匯出／撤回同意、忘記密碼、速率限制與監控。未提供憑證，因此尚未串接；API 對非本地模式採拒絕存取。

## 階段三：診斷與個別化

補齊有足夠題數及難度覆蓋的題庫，加入測驗藍圖、弱點複習與間隔複習、學校／補強／超前模式、教材解說與可及資產。先驗證診斷效度，再提供家長學習成效指標；目前少量題目只標示「觀察紀錄」。

## 階段四：營運與商業模組

免費核心教育功能維持。會員與贊助表已預留，但沒有支付 SDK、訂閱扣款或廣告曝光。接入金流前加入 webhook 驗章、冪等事件、退款與對帳測試；廣告需人工兒童安全審核，不以觀看換學習獎勵。家庭獎勵不涉及現金。

## 階段五：學校擴充及營運

教師／班級授權、學校多租戶、內容稽核、備份復原演練、負載與災難復原、無障礙人工驗收與真實使用者測試。尚未完成或承諾正式營運 SLA。
